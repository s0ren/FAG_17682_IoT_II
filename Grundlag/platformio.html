PlatformIO

Opsætning af VS Code og PlatformIO til ESP32

Forfatter
Uddannelse

Søren Magnusson

Data, TEC

Udgivet

23. november 2026

Ændret

23. november 2026

Før du kan skrive den første linje kode til ESP32, skal du have et værktøj, der kan oversætte koden og lægge den over på kortet. I faget bruger vi PlatformIO, som er en udvidelse til Visual Studio Code (VS Code). PlatformIO henter selv compiler, Arduino-framework og biblioteker, så alle i klassen bygger med præcis de samme versioner. Denne side fører dig fra en tom computer til et ESP32-kort, der blinker og skriver i Serial Monitor.

Formål

  • Du kan installere VS Code og PlatformIO på din egen computer.
  • Du kan oprette et PlatformIO-projekt til ESP32-DEVKIT-V1 med Arduino-frameworket og forklare, hvad de forskellige filer og mapper bruges til.
  • Du kan bygge, uploade og åbne Serial Monitor, og du kan sætte monitor_speed.
  • Du kan tilføje et bibliotek, både fra PIO Home og ved at skrive det i lib_deps.
  • Du kan finde fejlen, når upload ikke virker: forkert kabel, manglende driver, forkert port eller kortet, der ikke vil gå i upload-tilstand.

Målpinde

Siden arbejder med målpind 17, 20 og 24 (se Læringsmål).

Forudsætninger

  • En computer med Windows, macOS eller Linux, hvor du må installere programmer. Vejledningen her går ud fra Windows.
  • Internetforbindelse. Første gang henter PlatformIO flere hundrede MB.
  • Hardware: ESP32-DEVKIT-V1 og et USB-kabel, der kan overføre data (se USB-kablet).
  • Git installeret og grundlæggende kendskab til git init og git status (bruges i øvelse 4).

Installation

VS Code og PlatformIO IDE

  1. Hent og installer VS Code fra https://code.visualstudio.com/.
  2. Start VS Code, og åbn Extensions-visningen (Extensions view) med Ctrl+Shift+X eller ikonet med de fire firkanter i venstre side.
  3. Søg efter PlatformIO IDE. Vælg udvidelsen fra udgiveren PlatformIO (id’et er platformio.platformio-ide), og klik Install. Der findes andre udvidelser med lignende navne, så tjek udgiveren.
  4. Første gang du installerer en udvidelse fra en ny udgiver, spørger VS Code, om du stoler på udgiveren. Svar ja.

VS Codes egen vejledning Extension Marketplace har skærmbilleder af Extensions-visningen og knappen Install.

Første start

På Windows skal du ikke installere Python eller PlatformIO Core selv. PlatformIO IDE har sin egen Python og installerer PlatformIO Core (CLI, kommandolinjeværktøjet) i baggrunden, første gang udvidelsen starter. Det tager et par minutter, og du kan følge det nederst i vinduet. Når det er færdigt, beder VS Code dig måske om at genindlæse vinduet. Gør det. (På Linux skal pakken python3-venv være installeret, før PlatformIO kan installere sig.) Derefter dukker PlatformIO-ikonet (et myrehoved) op i venstre side, og PIO Home åbner.

PlatformIO lægger alle værktøjer i mappen .platformio i din brugermappe (på Windows %HOMEPATH%\.platformio). Det er her, compileren og Arduino-frameworket ender, når du bygger første gang. Derfor tager den første build også lang tid; de næste går hurtigt.

AdvarselUndgå æ, ø og å i stien

PlatformIO kan ikke bygge projekter, hvor den fulde sti indeholder tegn uden for ASCII, fx æ, ø og å. Det er en kendt fejl, som står i PlatformIO’s FAQ. Hvis dit brugernavn på Windows er fx Søren, så læg dine projekter i en mappe som C:\iot\ i stedet for under Dokumenter. Undgå også mellemrum i mappenavne, så slipper du for en anden type problemer.

Opret et projekt

  1. Klik på PlatformIO-ikonet i venstre side, og vælg PIO Home → Open. Eller klik på huset i statuslinjen nederst.
  2. Klik New Project. I guiden (Project Wizard) udfylder du:
    • Name: projektets navn, fx blink_test. Brug små bogstaver og _, ingen mellemrum eller æøå.
    • Board: skriv DOIT og vælg DOIT ESP32 DEVKIT V1.
    • Framework: Arduino.
    • Location: fjern fluebenet ved standardplaceringen, og vælg en mappe uden æøå og mellemrum (se boksen ovenfor).
  3. Klik Finish. Første gang henter PlatformIO platformen espressif32 og Arduino-frameworket. Det kan tage flere minutter.

Se skærmbillederne i PlatformIO’s Quick Start under trin 1 (PIO Home) og trin 2 (New Project).

Lås platformens version

Guiden skriver platform = espressif32 i platformio.ini. Uden versionsnummer bruger PlatformIO den version, der allerede er installeret på computeren, eller den nyeste, hvis der ikke er nogen. Så kan to elever, der har installeret med en måneds mellemrum, få forskellige versioner af Arduino-frameworket. Ret derfor linjen til:

platformio.ini
platform = espressif32@8.0.0

Version 8.0.0 af platformen indeholder Arduino-ESP32 version 3.3.x. Bemærk, at det er to forskellige versionsnumre: platformen (8.0.0) er PlatformIO’s pakke, og Arduino-ESP32 (3.3.x) er frameworket inden i den. Platform 7.x indeholdt fx stadig Arduino-ESP32 2.x. Det er den version, siderne på dette site er tjekket mod, så koden her opfører sig ens hos alle. PlatformIO anbefaler selv at låse versionen, så en build kan gentages.

Vil du senere skifte version, retter du bare tallet og bygger igen. PlatformIO henter selv den nye version. Se, hvilke versioner der findes, på platformens udgivelser på GitHub. Bemærk, at et skift i hovedversion (fx fra Arduino-ESP32 2.x til 3.x) kan kræve ændringer i koden.

Projektets opbygning

Når projektet er oprettet, ser mappen sådan ud:

blink_test/
├── .pio/            ← byggede filer og hentede biblioteker (laves af PlatformIO)
├── .vscode/         ← indstillinger til VS Code (laves af PlatformIO)
├── include/         ← dine egne header-filer (.h)
├── lib/             ← dine egne biblioteker, ét pr. undermappe
├── src/
│   └── main.cpp     ← dit program
├── test/            ← automatiske tests
├── .gitignore
└── platformio.ini   ← projektets opsætning
Fil eller mappe Hvad den bruges til
platformio.ini Projektets opsætning: board, framework, platformens version, monitor_speed og biblioteker. Én sektion [env:…] pr. miljø (environment).
src/ Kildekoden. Programmet starter i src/main.cpp, som skal begynde med #include <Arduino.h> for at kunne bruge Arduino-funktionerne.
include/ Header-filer (.h), som main.cpp kan inkludere med #include "fil.h". Fx secrets.h på siden om WiFi.
lib/ Biblioteker, du selv skriver og kun bruger i dette projekt. Biblioteker fra nettet skal ikke herind; dem skriver du i lib_deps.
test/ Unit-tests til PlatformIO’s testværktøj. Bruges ikke i begyndelsen.
.pio/ Alt det, PlatformIO laver selv: oversatte filer, den færdige firmware og bibliotekerne fra lib_deps (i .pio/libdeps/). Kan altid laves igen.
.vscode/ Filer, som PlatformIO genererer til VS Code, fx stier til header-filer, så autofuldførelse virker.

.gitignore

Det, der kommer i git, er det, en anden skal bruge for at bygge projektet: platformio.ini, src/, include/, lib/ og test/. .pio/ skal ikke med. Den fylder meget, og PlatformIO laver den igen ved næste build. Det samme gælder de filer i .vscode/, der indeholder stier fra din egen computer.

Når PlatformIO opretter et projekt i VS Code, laver det en .gitignore med dette indhold (kun hvis der ikke er en i forvejen):

.gitignore
.pio
.vscode/.browse.c_cpp.db*
.vscode/c_cpp_properties.json
.vscode/launch.json
.vscode/ipch

Lad den stå. Har du hemmeligheder som WiFi-passwords i projektet, skal de også i .gitignore (se WiFi).

Byg, upload og Serial Monitor

Nederst i VS Code, i statuslinjen, har PlatformIO en række små knapper. Fra venstre:

Knap Hvad den gør Genvej
Hus Åbner PIO Home
✓ Build Oversætter projektet. Fejl vises i terminalen. Ctrl+Alt+B
→ Upload Bygger, hvis det er nødvendigt, og lægger programmet over på ESP32. Ctrl+Alt+U
Skraldespand Clean Sletter de byggede filer i .pio/build/, så næste build starter forfra.
Stik Serial Monitor Åbner en terminal, der viser det, ESP32 skriver med Serial. Ctrl+Alt+S
Terminal Åbner en terminal med PlatformIO’s kommandolinje (pio).

De samme kommandoer findes under PlatformIO-ikonet i venstre side under Project Tasks, sorteret efter miljø. Se skærmbilledet i PlatformIO’s dokumentation under PlatformIO Toolbar og Task Explorer.

Clean bruger du, når en build opfører sig mærkeligt, fx efter du har skiftet platformens version eller flyttet filer. Ellers er der ingen grund til det: så skal alt bare oversættes igen.

monitor_speed

ESP32 og Serial Monitor skal være enige om, hvor hurtigt de sender: baud rate, altså bit pr. sekund. I programmet sættes den med Serial.begin(115200). PlatformIO’s Serial Monitor bruger 9600, hvis du ikke skriver andet. Derfor skal hvert projekt have denne linje i platformio.ini:

platformio.ini
monitor_speed = 115200

Er de to tal forskellige, ser du tilfældige tegn i Serial Monitor i stedet for tekst.

Du lukker Serial Monitor med Ctrl+C i terminalen eller ved at lukke terminalen. Du behøver ikke lukke den, før du uploader: PlatformIO lukker den selv under upload og åbner den igen bagefter. Men et andet program, der har porten åben (Arduino IDE, PuTTY, en anden VS Code), blokerer upload.

USB-forbindelsen

USB-kablet

Mange USB-kabler, især dem der følger med powerbanks og små apparater, kan kun lade og har ingen dataledninger. Med sådan et kabel lyser den røde lysdiode på kortet, men computeren ser ingen port, og upload fejler. Har du problemer, så prøv et andet kabel, før du leder efter fejlen andre steder.

USB-serielchippen og driveren

ESP32 har ikke selv USB. På DEVKIT-V1 sidder der en lille chip ved USB-stikket, som oversætter mellem USB og ESP32’s serielle port (UART). Det originale DOIT-design bruger en CP2102 fra Silicon Labs, men mange kopier bruger en CH340 fra WCH. Navnet står på chippen, hvis du kigger med lup.

Windows 10 og 11 installerer som regel driveren selv, når du sætter kortet i. Hvis der ikke dukker en port op:

  • CP2102: hent driveren CP210x USB to UART Bridge VCP Drivers fra Silicon Labs.
  • CH340: hent driveren fra producenten WCH, CH341SER.

Find COM-porten

På Windows hedder serielle porte COM3, COM4 osv. Sådan finder du den, kortet har fået:

  1. Åbn Enhedshåndtering (højreklik på Start-knappen).
  2. Fold Porte (COM og LPT) ud.
  3. Tag kortet ud og sæt det i igen. Den port, der forsvinder og kommer igen, er din. Den hedder fx Silicon Labs CP210x USB to UART Bridge (COM3) eller USB-SERIAL CH340 (COM5).

Espressif viser det med skærmbilleder under Check Port on Windows.

PlatformIO finder normalt selv porten. Har du flere serielle enheder tilsluttet, og vælger den forkert, så skriv porten i platformio.ini:

platformio.ini
upload_port = COM5
monitor_port = COM5

Fjern linjerne igen, før du afleverer, for porten er sikkert en anden på lærerens computer.

“Failed to connect”: BOOT-knappen

Ved upload nulstiller værktøjet esptool normalt ESP32 og sætter den i upload-tilstand (download mode) automatisk. Mens det sker, skriver det Connecting.... med flere og flere prikker. Nogle kort når ikke at skifte, og så ender upload med en fejl, der begynder sådan:

A fatal error occurred: Failed to connect to ESP32: ...

Resten af linjen afhænger af esptool-versionen, fx Timed out waiting for packet header, No serial data received eller Wrong boot mode detected.

Løsningen er at sætte kortet i upload-tilstand i hånden med knapperne ved USB-stikket:

  1. Start upload.
  2. Når der står Connecting...., så hold BOOT-knappen nede.
  3. Slip den, når uploaden er gået i gang, og der står Writing at ….

Virker det ikke, så hold BOOT nede, tryk kort på EN (reset), og slip derefter BOOT. BOOT-knappen trækker GPIO 0 til GND, og det er det, der får ESP32 i upload-tilstand ved opstart.

Efter upload starter programmet normalt af sig selv. Gør det ikke, så tryk på EN.

Eksempel: test af build og upload

Et lille program, der kun skal vise, at det hele virker: den indbyggede lysdiode på GPIO 2 blinker, og ESP32 skriver i Serial Monitor hvert sekund. Selve programmeringen gennemgås på siden om Hello World.

platformio.ini
[env:esp32doit-devkit-v1]
platform = espressif32@8.0.0
board = esp32doit-devkit-v1
framework = arduino
monitor_speed = 115200
src/main.cpp
#include <Arduino.h>

// Konfiguration
const int LED_PIN = 2;                 // indbygget lysdiode på DEVKIT-V1
const unsigned long INTERVAL_MS = 1000; // tid mellem skift

unsigned long sidsteSkift = 0;
bool ledTaendt = false;

void setup() {
  Serial.begin(115200);  // skal passe med monitor_speed
  pinMode(LED_PIN, OUTPUT);
  Serial.println("PlatformIO virker!");
}

void loop() {
  // millis() i stedet for delay(), så loop() aldrig står stille
  if (millis() - sidsteSkift >= INTERVAL_MS) {
    sidsteSkift = millis();
    ledTaendt = !ledTaendt;
    digitalWrite(LED_PIN, ledTaendt ? HIGH : LOW);
    Serial.printf("Kørt i %lu s\n", millis() / 1000);
  }
}

Klik Upload og derefter Serial Monitor. Lysdioden skal blinke, og der skal komme en linje hvert sekund. Ser du ikke linjen PlatformIO virker!, er det fordi programmet startede, før Serial Monitor var åben. Tryk på EN, så starter programmet forfra.

Biblioteker med lib_deps

Biblioteker fra nettet står i lib_deps i platformio.ini. Senest når du bygger, henter PlatformIO dem fra PlatformIO-registret og lægger dem i .pio/libdeps/. Du skal ikke kopiere filer selv.

Du kan få linjen i lib_deps på to måder: vælge biblioteket i PIO Home, eller skrive linjen selv. Begge dele ender med den samme linje i platformio.ini, og det er kun den linje, der tæller. PIO Home er bare en hjælp til at finde det rigtige navn og den nyeste version.

Eksemplet er biblioteket ezButton, som siden om Debouncing bruger.

Måde 1: vælg biblioteket i PIO Home

  1. Åbn PIO Home (huset i statuslinjen), og klik på Libraries i menuen til venstre.
  2. Søg efter ezButton.
  3. Klik på biblioteket i resultatlisten. Tjek, at ejeren er arduinogetstarted (vises som “Arduino Get Started”); der kan være flere biblioteker med lignende navne. Add to Project henter biblioteket med det samme.
  4. Klik Add to Project.
  5. Vælg dit projekt i dialogen, og klik Add.

PlatformIO skriver nu en linje i lib_deps i projektets platformio.ini med ejer, navn og den nyeste version, fx arduinogetstarted/ezButton@^1.0.6. Åbn filen, og se efter.

PlatformIO’s egen dokumentation har kun et enkelt skærmbillede af bibliotekssiden i PIO Home under Library Manager og beskriver ikke trinnene. Random Nerd Tutorials viser hele forløbet med skærmbilleder under Installing ESP32/ESP8266 Libraries on PlatformIO IDE i artiklen under Læs videre.

Måde 2: skriv lib_deps selv

Du kan også skrive linjen direkte i platformio.ini. Det er hurtigere, når du allerede kender navnet, fx fra en opgave eller en side her på sitet:

platformio.ini
[env:esp32doit-devkit-v1]
platform = espressif32@8.0.0
board = esp32doit-devkit-v1
framework = arduino
monitor_speed = 115200
lib_deps = arduinogetstarted/ezButton@^1.0.6

Navnet består af tre dele:

  • arduinogetstarted er ejeren i registret. Tag det med, så du får det rigtige bibliotek, hvis flere har samme navn.
  • ezButton er bibliotekets navn.
  • @^1.0.6 er versionen: ^ betyder “1.0.6 eller nyere, men stadig 1.x.x”. Så får du fejlrettelser og nye funktioner, men ikke en ny hovedversion, der kan ændre de funktioner, du bruger. Det er den form, PlatformIO anbefaler.

Flere biblioteker skrives på hver sin linje, rykket ind:

platformio.ini
lib_deps =
  arduinogetstarted/ezButton@^1.0.6
  knolleary/PubSubClient@^2.8

Biblioteker, der følger med Arduino-frameworket, som WiFi.h, skal ikke i lib_deps.

Øvelser

  1. Installer VS Code og PlatformIO, og opret projektet blink_test. Byg det. Hvor lang tid tager den første build, og hvor lang tid tager den næste? Forklar forskellen.
  2. Find kortets COM-port i Enhedshåndtering. Upload testprogrammet, og åbn Serial Monitor. Aflever et skærmbillede af Serial Monitor.
  3. Ret monitor_speed til 9600, men lad Serial.begin(115200) stå. Hvad ser du i Serial Monitor? Ret det tilbage.
  4. Tilføj ezButton fra PIO Home med Add to Project. Se i platformio.ini, hvilken linje der er kommet i lib_deps, og sammenlign den med linjen i Måde 2. Byg projektet. Find biblioteket i .pio/libdeps/. Kør derefter git init og git status i projektmappen. Kommer .pio/ med? Hvorfor ikke?
  5. Ret INTERVAL_MS til 200, og upload igen. Upload så en gang, mens du holder BOOT-knappen nede, som beskrevet under BOOT-knappen. Virker det også?
  6. Ekstra: Klik Clean, og byg igen. Sammenlign tiden med de to builds fra øvelse 1. Hvad blev slettet af Clean, og hvad lå der stadig i .platformio i din brugermappe?

Typiske fejl

  • Ingen port dukker op: Kablet kan kun lade, eller driveren til USB-serielchippen mangler. Prøv et andet kabel først.
  • Failed to connect to ESP32: Kortet kom ikke i upload-tilstand. Hold BOOT nede under Connecting..... Tjek også, at et andet program ikke har porten åben.
  • Tilfældige tegn i Serial Monitor: monitor_speed passer ikke med Serial.begin().
  • Serial Monitor er tom: Programmet skrev sin tekst, før monitoren var åben. Tryk på EN. Eller Serial.begin() mangler.
  • Build fejler med mærkelige fejl om stier eller tegn: Projektets sti indeholder æ, ø, å eller andre tegn uden for ASCII. Flyt projektet.
  • Access is denied under installationen: Et antivirusprogram blokerer PlatformIO. Se PlatformIO’s FAQ.
  • fatal error: ezButton.h: No such file or directory: Biblioteket står ikke i lib_deps, eller navnet er stavet forkert.
  • Koden virker hos dig, men ikke hos læreren: Platformens version er ikke låst, så I bygger med forskellige versioner af Arduino-frameworket.
